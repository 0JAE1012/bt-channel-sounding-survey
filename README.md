# Bluetooth Channel Sounding — 논문 · 표준 서베이

**https://0jae1012.github.io/bt-channel-sounding-survey/**

Bluetooth Channel Sounding(CS)의 **보안**을 연구하기 위한 문헌·표준 데이터베이스입니다.
논문 목록이 아니라 연구 상태를 담는 것이 목적입니다 — 이 분야가 어떻게 발전했고,
무엇이 이미 깨졌고, 무엇이 아직 가정이며, 그래서 다음에 무엇을 해야 하는지.

이 저장소는 **생성물만** 담습니다. 수집 스크립트와 작업 메모는 비공개 저장소에 있고,
데이터가 바뀔 때마다 여기로 동기화됩니다.

```
index.html            대시보드 (빌드 스텝 없음 — JSON을 런타임에 fetch)
data/papers.json      논문 레코드
data/standards.json   표준·규격 문서 레코드
data/insights.json    연구 상태 (주제 · 인사이트 · 할 일 · 실험 이력 · 읽는 순서)
data/research.json    판단 (Landscape · Claims · Attack×Defense · RQ · Reproduction)
CHANGELOG.md          매 서베이 실행이 무엇을 바꿨는지
```

## 사이트 구성

| 탭 | 무엇을 보는가 |
|---|---|
| **Landscape** | 분야의 계보와 현재 위치. What We Know / Broken / Still Assumed / Open Questions |
| **논문** | 107편의 레코드. 주제·구분·관련도·확인 상태·기술 축으로 거른다 |
| **표준 문서** | Core Spec, RAS/RAP, 802.15.4z/4ab, CCC Digital Key 등 |
| **인용 관계** | 논문 사이의 인용 그래프 (연도축, 원 크기 = 코퍼스 내 피인용) |
| **연구 계보** | 인용과 다른 축 — "A가 B의 무엇을 했는가"(extends / attacks / defends / …) |
| **공격 × 방어** | 공격별로 각 방어 요소가 무엇을 했는지의 표. **?가 몰린 칸이 실험 후보** |
| **주장과 근거** | 업계·문헌의 주장과 그에 대한 반증, 그리고 아직 못 한 실험 |
| **연구 질문** | RQ 단위로 아는 것 / 모르는 것 / 다음 실험 |
| **재현** | 논문 재현 진행 상황. 각 항목에 근거(실험 id·수치) 표시 |
| **기록** | CHANGELOG |

## 데이터 스키마

`papers.json`의 논문 하나는 서지정보와 함께 **실험 장비 · 소프트웨어 · 실험 결과 · 한계**를
구조화해 담고, 여기에 "이 논문이 CS 보안 연구에 어떻게 쓰이는가"(`relevance_note`)를 붙입니다.

분류 축은 셋입니다.

- `category` — 무엇을 하는 논문인가: `attack` / `defense` / `analysis` / `measurement` /
  `estimation` / `protocol` / `survey`
- `tech` — 어느 무선 기술인가: `ble-cs` / `uwb` / `wifi` / `other` (배열, 복수 가능)
- `tier` — 어디에 실렸는가: `top4`(S&P·USENIX·CCS·NDSS) / `wireless` / `journal` /
  `preprint` / `thesis` / `other`

논문 사이의 연결도 둘로 나눕니다.

- `cites` — **A가 B를 인용했다.** 확보한 전문의 참고문헌을 실제로 대조해서만 기록합니다.
- `relations` — **A가 B의 무엇을 했다.** `extends` / `implements` / `attacks` / `defends` /
  `bypasses` / `contradicts` / `generalizes` / `applies-to` / `fails-against` 등.
  인용하지 않아도 관계는 성립할 수 있고, 연구 계보를 읽을 때 필요한 것은 이쪽입니다.

## 검증 배지 — 이 프로젝트의 핵심 규칙

**추측한 값을 사실처럼 기록하지 않습니다.**

| 배지 | 뜻 |
|---|---|
| `확인완료` | 원문 전문을 열어 대조함 |
| `일부확인` | 초록·서지정보 수준까지만 확인 |
| `확인필요` | 검색 결과 기반 — 원문 대조 안 됨 |
| `미대조` | 해당 장비/소프트웨어 항목을 원문에서 확인하지 못함 |

원문에서 확인하지 못한 장비명·수치·버전은 `"확인 필요"`로 남기고 `*_verified: false`를
유지합니다. 그럴듯한 값을 채워 넣으면 다음 실행에서 스스로를 속이게 되기 때문입니다.
사이트가 이 플래그를 배지로 드러내므로 미확인 항목이 눈에 보이고 다음 차례에 먼저 처리됩니다.

인사이트와 실험에는 **근거의 무게**를 따로 표시합니다 —
`hypothesis`(문헌과 추론뿐) · `simulated` · `trace-replay`(실측 trace에 합성 조작 주입) ·
`conducted`(케이블 실험) · `ota`(무선 실행) · `commercial`(상용 기기 end-to-end).
케이블 실험이 답할 수 있는 것과 없는 것이 다르기 때문에 나눕니다.

`research.json`의 모든 주장은 `evidence`로 실제 레코드 id를 가리키고, 배포 전 검증기가
그 id의 존재를 대조합니다. **사이트에 적힌 문장은 전부 근거로 되짚을 수 있습니다.**

## 서베이 방법

매 실행이 같은 절차를 탑니다.

1. **프로시딩 목차 직접 훑기** — 키워드 검색만으로는 반드시 빠집니다. 실제로 제목에
   Bluetooth도 Channel Sounding도 없는 최상위 관련 논문을 그렇게 놓친 적이 있습니다.
2. **키워드 질의 행렬** — 주제 축, 신호처리 축, 방어·이론 축, 인접 기술 비교군
3. **기존 항목 보강** — 매 실행 최소 2건의 원문을 실제로 열어 장비·수치·한계를 채웁니다.
   PDF는 다운로드 후 텍스트 변환해 읽습니다(WebFetch는 PDF를 파싱하지 못합니다).
4. **참고문헌 캐기** — 확보한 전문의 참고문헌이 가장 효율적인 신규 발굴 경로입니다.
5. **인용 관계 추출** — 전문의 참고문헌을 정규화 제목으로 대조합니다.
6. **표준 점검** — Bluetooth SIG 릴리스, RAS/RAP, IEEE 802.15.4ab, CCC Digital Key

## 자동 갱신

**3일 주기**로 에이전트가 위 절차를 한 번 돌고, 변경이 있으면 커밋합니다.
푸시되면 CI가 데이터를 검증한 뒤 이 사이트를 재배포합니다. **검증 실패 시 배포되지 않으므로
깨진 데이터가 사이트에 올라가지 않습니다.**

검증 항목: 세 JSON 파싱 · 필수 필드 · enum 값 · 중복 id · 같은 제목/DOI 중복 등록 ·
인용 관계의 유령 id·자기 인용·시간 역행 · `citation_edges` 재계산 일치 ·
`relations` 대상 존재 · `research.json`의 모든 근거 id 존재 · 인사이트 `evidence` 유령 id ·
`verified` 항목의 원문 주소 유무 · CHANGELOG와 데이터 날짜 정합 ·
그리고 직전 커밋 대비 퇴행(논문 수 감소, 검증 등급 하락, 확인 항목 급감).

변경이 없어도 `last_run`만 갱신해 커밋합니다. 사이트 상단의 신선도 배너가 이 값을 보고
"작업이 조용한 것"과 "작업이 죽은 것"을 구별합니다.

## 재현

재현 탭의 각 항목에는 근거가 붙어 있습니다 — 어느 실험에서 나온 수치인지, 무엇이 막혀 있는지.
진행률은 **근거가 있을 때만** 채웁니다. 미착수는 0으로 두고 `basis`에 그 사실을 적습니다.

## 인용

`data/papers.json`을 그대로 쓰거나, 사이트에서 BibTeX를 받아 쓸 수 있습니다.
`verification`이 `verified`가 아닌 항목에는 주의 주석이 붙고, 게재 정보가 미확인이면
`UNCONFIRMED VENUE`로 표시됩니다. 서지정보가 확정되지 않은 것을 모르고 인용하는 사고를
막기 위한 것입니다.

## 라이선스와 범위

수집한 논문의 저작권은 각 저자·출판사에 있습니다. 이 저장소는 **서지정보와 그에 대한 메모**만
담으며 논문 전문을 재배포하지 않습니다. 요약·관련도 메모는 이 연구 목적의 독자적 기술입니다.
